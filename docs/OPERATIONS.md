# 批次操作

1. 用带异常样例做阶段预览，查看列数、必填值和冲突记录。
2. 执行批次后，在业务阶段定位异常分组并核对原始记录键。
3. 修复来源文件，重新上传并执行。历史批次保留供复核。
4. 对账无差异且无坏行时可签发。对仍有差异的版本可填写暂缓意见。
5. 导出复核证据并保存于交接记录。

## 基准换版

1. 在「校准版本」面板核对本版版本、生效版本和受影响业务组；每行批次结果都标出所用基准版本，冻结的已签发读数带「（冻结）」。
2. 晚到同步数据带来新基准时，未签发范围立即采用新基准，并列在「本次变化的读数」里（状态「已采用新基准」）。
3. 已签发读数保持原值、原判定和原基准版本；若新基准下重算会得到别的值，只在表里如实列出（状态「保持签发值 · 冻结」），不会改写。
4. 受影响范围内有无法闭合的组（外推、超差、缺读数、已签发读数来源变了）时整版阻断，签发按钮不可用；修正来源后重跑。
5. 签发即切换到新版本。切换失败时旧版本与旧数据原样保留，可重试；已签发批次带着签发时快照，后续换版不会改写它。

单文件 256 KiB，最多 2000 条逻辑记录。容器重启后保留批次与版本历史。恢复时使用原 Docker Compose 数据卷。
